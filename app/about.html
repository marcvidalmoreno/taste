Why

I make images for my posts and wallpapers, and I know what I like when I see it. Over the years I saved about 1,000 wallpapers. An image model can't read that folder, but it can read a written description.

So this project turns the folder into words: styles with a palette, light, composition, medium, mood and, just as important, what to avoid. Then every image I make, and how I rate it, feeds back into those words. The taste is meant to grow from evidence, not from guesses.

The wallpapers belong to the people who made them. They stay on my laptop. Only the descriptions and the images I generate are mine to show.

History

  2. 13 Nov 2026 Codex route. Images made with ChatGPT through Codex CLI, on my plan, with no API key and no bill. One image per run, every run logged with its cost in allowance. Variations, contact sheets, ratings and a "distil" step that turns ratings into style edits.
  3. 13 Nov 2026 Taste rebuilt from zero. Colour alone found the right style only 36 % of the time. Every wallpaper was tagged by eye on contact sheets (subject, medium, mood, light) and grouped into fourteen styles, each approved one by one. Palettes are measured from the images.
  4. 13 Nov 2026 This web app. Look at a batch, mark keep / almost / no with a reason, save, start variations, see ratings per style.
  5. 14 Nov 2026 Gallery, Taste and About pages. Everything I've made in one place, and the styles shown with my own images as examples.
  6. 15–19 Nov 2026 More collections, more variety. New styles from my ART folder and later collections, a few dropped again after testing, and several looks per style (light, framing, mood) so images in one style stop looking alike.
  7. 18 Nov 2026 Thumbs. Rating became thumbs up or down, with an optional why, instead of keep / almost / no.
  8. 21 Nov 2026 The app is the interface. Runs start from the page and wait in one queue; remix and variations from any image; a thumb counts the moment I press it and steers the style's next runs; I can change a style from wherever I see its images; and every 20 ratings Codex suggests style edits that I apply or skip. Claude and Codex do the rest out of sight.

How it works

  1. Styles. Each style is one JSON file in taste/styles/. build_taste.py turns them into short prompt blocks in taste/taste.json.
  2. Generate. I start a run on the New run page; it joins one queue. codex_run.py starts one fresh codex exec per image with a style and a subject (Codex writes fresh subjects when I leave them empty). About a minute and ~95k tokens per image (mostly cached).
  3. Vary and remix. Variations change one thing at a time: palette, subject, composition or mood, with the image as a reference. A remix changes what I say; Codex rewrites the prompt and I read it first.
  4. Rate. Thumbs up or down, with a short why. A thumb is saved at once and can be taken back. Each one re-weights the style's options (leaning.py), so new runs lean toward what I liked; the Taste page shows how.
  5. Change a style. From any image, the Gallery or the Taste page: I say what should change, Codex proposes the smallest edit, I untick what I don't want and apply. Or I add my own words as a "lean towards" or an "avoid" line. Every edit can be undone.
  6. Suggestions. Every 20 ratings Codex reads the latest thumbs and whys and suggests edits per style. A chip in the header says when one waits; I apply or skip each one.

The app is plain HTML, CSS (Pico.css) and JavaScript modules, served by a small Python server on 127.0.0.1 only. No framework, no build step. Images, ratings and logs stay in generated/codex/, which git ignores.

Decisions

Styles by eye, not by colour
Colour clustering was quick but wrong two times out of three. Tagging by eye took longer and gives styles I recognise as mine. Tools still offer a top-3 guess, and I confirm it.
Codex for images, Claude Code for the taste
One tool generates, the other one thinks. Codex makes the images and drafts text (subjects, prompts, style proposals) but never edits a style file itself; a style changes only when I press Apply, or when I OK Claude Code's set of edits in chat. Files are the hand-off between them.
One change per variation
If a variation changes palette and subject at once, I can't tell which one I liked. One change, one lesson.
Every mark counts at once
Until 21 Nov marks were drafts until I pressed Save. Now a thumb is saved the moment I press it and pressing it again takes it back: one step less, and nothing lost if I close the tab.
The app is the interface
I give feedback where I feel it, on the image or the style, as a thumb, a remix or a few words. No scripts or chat steps on my side; Claude and Codex pick it up from the files.
Local first
The wallpapers and every reference image stay private. The app listens on this machine only.
Measure the allowance, don't guess it
Every run logs the allowance read from Codex's own log, so the budget (about 40 images a week) rests on numbers.

How we work

Three of us, each with a clear job:

  • Me: I look, rate and decide, in this app. Every style edit needs my OK.
  • Claude Code: owns the taste files, reads my notes and ratings, proposes edits, builds the tools and this app, commits my style edits, and writes a changelog entry with an undo line for every change.
  • Codex CLI: makes the images, one fresh run per image, and drafts subjects, remix prompts and style suggestions for me to read. It never changes a style on its own.

The rules for Claude Code are in the repo's CLAUDE.md: stop and report after one failed retry, ask before spending a large share of the allowance, check every push for private data.
